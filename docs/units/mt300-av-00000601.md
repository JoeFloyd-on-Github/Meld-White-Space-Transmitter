# Unit notes: MT300-AV, serial 00000601

Facts specific to **one physical unit** (serial `00000601`). These do **not**
generalize to every MT300 — bad-block maps, MACs, and which bank is healthy are
per-unit. The general bootloader / flash / bank reference is
[`../bootloader.md`](../bootloader.md); getting a shell is
[`../device-access.md`](../device-access.md).

> **Privacy / security.** This unit's `/etc/config/sbi` holds the previous owner's
> contact details, and `/disk/www/.htpasswd` holds the web-UI password hash.
> **Neither is reproduced here or anywhere in this repo** — the PII for the reasons
> in [`../device-access.md`](../device-access.md), and the password hash because it
> is crackable. Both are recorded only in the owner's local notes/backup.

## NAND health — the reason this unit needed recovery

`nand bad` reports **209 bad erase blocks**, and they are **not** scattered: every
one falls in a single contiguous zone.

- Range: **`0x03600000` .. `0x058e0000`** (~36 MiB, ~280 erase blocks of 128 kB).
- That range is **exactly the `RootFS_1` partition** (`mtd7`, 0x3600000–0x5900000)
  — the **bank B** root filesystem.
- **~75 %** of that partition's blocks are bad; **~5.1 %** of the whole 512 MiB
  device. The rest of the chip (bank A kernel/rootfs, both app partitions, the
  bootloader/env region) shows **no** reported bad blocks.

The full offset list is in
[`../captures/uboot-console-2026-11-22.txt`](../captures/uboot-console-2026-11-22.txt).

## Bank status and the recovery performed

As received, the saved U-Boot env had **`current_active=1`** (bank B). Because
bank B's `RootFS_1` sits on the destroyed NAND region above, the unit **booted but
then hung**:

```
VFS: Mounted root (yaffs filesystem) on device 31:7     (mtdblock7 = RootFS_1)
Freeing unused kernel memory: 192k freed
do_page_fault() #2: sending SIGSEGV to init             -> hang, no shell, no network
```

**Bank A is healthy.** `current_active=0` boots `Linux_Kernel_0` + `RootFS_0`
(`mtdblock6`) with no SIGSEGV, brings up networking, starts `telnetd`, and runs the
AV app.

**Action taken (2026-11-22), with the owner's authorization:** switched the default
bank to A and persisted it —

```
setenv current_active 0
saveenv            # Saving Environment to NAND... Erasing Nand...Writing to Nand... done
```

Verified: on a clean `reset` with no intervention the unit now autoboots bank A to
a working shell. The procedure is the general one in
[`../bootloader.md`](../bootloader.md) §5; this records that it was applied to this
unit and that bank A is the good one here.

## What runs on bank A (this unit)

- Active app: **`av_streamer`** (HDMI input → MPEG, DVO output) from `/disk/Meld/AV30`.
  This bank is the **AV streaming** personality of the box.
- The white-space pieces are present on the rootfs but **not** the active service
  here: `/usr/bin/whitespaceagent` (9.1 MB), `/usr/bin/MeldAgent` (3.1 MB),
  `wsagent_start` / `wsagent_stop`. `MeldAgent` runs once at boot to read the radio
  (reports FCC ID / serial / channel, **TX disabled**).
- `thttpd` web UI on port 80; `telnetd -l /bin/sh` (root, no password) on port 23;
  UPnP/SSDP on 1900 advertising `MELD_BOX_00000601`.

## Network access for this unit

- On bank A, `setipeth0` brings eth0 up at **`172.16.200.39/24`**. If the PC is on a
  different subnet, either add a route / second IP in `172.16.200.0/24`, or set a
  temporary address over the serial shell, e.g.
  `ifconfig eth0 192.168.1.195 netmask 255.255.255.0 up` (**RAM-only**, reverts to
  172.16.200.39 on reboot).
- Telnet root shell and `nc` file transfer as in
  [`../device-access.md`](../device-access.md).
